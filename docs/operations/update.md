# 更新镜像

稳定版使用`latest`，测试版使用`dev`，版本标签使用`v*.*.*`。生产部署建议固定版本标签；想跟随稳定分支时再使用`latest`。

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 app
```

`docker compose up -d`会用已拉取镜像重建需要更新的容器，不会删除持久化目录。

## 更新前检查

- `data/`、`temp/`和内置AList的`alist/`确实挂载到宿主机。
- 阅读[版本与升级记录](../reference/releases)中的迁移说明。
- 涉及 AList / OpenList 版本变化时，先备份对应数据目录并阅读[AList / OpenList升级](../alist/upgrade)。
- 大版本回滚前先导出旧镜像可读取的JSON快照。
- `v2.5.1`会把schema 10数据库升级到schema 11，增加手动来源类型与相关索引；`v2.5.2`、`v2.5.3`、`v2.5.4`和`v2.5.5`沿用schema 11，不再执行数据库结构迁移，不批量探测在线内容、不重写既有关系。`v2.5.2`到`v2.5.5`只是补丁版本更新。升级前会在`data/backups`生成一致性备份，启动期间服务暂不可用；回滚到`v2.5.0`或更早镜像时，先恢复升级前SQLite备份，不能让旧镜像直接打开schema 11数据库。
- 真实升级时，容器日志会显示源schema、目标schema、开始、完成或失败以及总耗时；普通启动不会重复输出迁移日志。失败日志只说明没有提交数据库变更，不包含数据库路径、备份文件名、SQL正文或业务数据。
- 更新前确认没有等待执行、执行中、自动重试或失败待处理的归档删除任务；这些任务会阻止迁移导出和业务状态清理，且开始后不能取消。

## 更新后检查

1. 顶部版本与预期镜像一致。
2. 容器没有反复重启。
3. SQLite完整启动，持久任务和冷却恢复。
4. schema 11迁移日志完成，在线内容按钮可打开，归档库全局、账号和收藏夹目录均可正常翻页，队列可恢复持久上传与远端确认。
5. 队列没有同一BV的立即失败循环。
6. AList / OpenList 上传与远端确认正常。

拉取失败不会替换当前运行容器；看到旧容器仍在运行并不代表更新成功。
