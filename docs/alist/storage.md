# 添加网盘与WebDAV路径

先在 AList 或 OpenList 后台添加目标网盘存储，例如挂载到：

```text
/阿里云盘
```

再回到 BFB 全局设置，将“目标存储路径”填写为：

```text
/阿里云盘/bili-backup/videos
```

路径必须以`/`开头。BFB会根据目录布局继续创建账号、收藏夹或视频层级。

## 目录布局

| 设置 | 示例 |
| --- | --- |
| 用户名 / 收藏夹名 / 视频 | `/目标/账号/收藏夹/文件.mp4` |
| 收藏夹名 / 视频 | `/目标/收藏夹/文件.mp4` |
| 仅视频文件 | `/目标/文件.mp4` |

首次使用建议保留默认“用户名 / 收藏夹名 / 视频”，多账号同名收藏夹不容易碰撞。

## 连接检查

全局设置中的“只读检查存储连接”会使用当前尚未保存的地址、账号、密码和目标路径，最多等待15秒。它只执行WebDAV目录属性读取，不会创建、上传、复制、移动或删除文件。检查通过仅说明端点、认证和归档目录当前可读，不能代替写入测试，也不会自动保存表单。

保存后先用一个小视频跑通以下动作：

1. BFB能列出目标目录。
2. PUT后进入“已上传·确认中”。
3. 稍后能读取同名文件的精确大小。
4. AList 或 OpenList 后台能下载该文件。

普通新归档不要求 MOVE：它使用正式路径条件PUT和持久Session证明。当前来源已有完整旧归档时优先保留旧版；未知同大小、异大小或旧证明漂移时先进入“待处理”。只有本地整组文件、任务Session和候选父目录均通过预检，管理员确认“生成隔离候选”后才会把整组文件PUT到独立`_conflicts`目录，正式旧路径保持不变。画质重调和批量重命名会独立探测 MOVE/COPY，优先 MOVE，只有明确不支持 MOVE 且 COPY 已校验成功时才使用 COPY+DELETE。路径迁移仍按自己的 COPY 预检和原有旧目录清理流程执行。
