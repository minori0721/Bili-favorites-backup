# 下载与上传限速

在「设置 → 队列与重试」分别填写下载总限速和上传总限速，单位为 MB/s，可填写小数，`0` 表示不限速。保存后，对正在传输的任务和后续任务生效，不需要重启或重新下载。

同一方向的备份任务共用额度。例如下载总限速为 2 MB/s，同时下载两个视频时，合计按约 2 MB/s 控制。限速按文件数据计算，短时读写和速度采样会有波动。并发数决定同时进行多少任务，上传间隔决定两次上传何时开始，它们与总限速分别生效。

普通归档、单独归档、画质升级和恢复任务使用相同的限速规则。播放和 B站信息查询不受这两个设置影响。限速等待期间任务继续保有租约；正常慢速下载不会因为低于原来的低速阈值而被重新下载，真正无进展和网络错误仍按恢复规则处理。

## 上传经过存储服务

上传链路是「本程序 → AList / OpenList → 网盘」。这里的上传限速控制本程序发送文件流的速度。存储服务可能先缓存完整文件或分片，再发往网盘，因此网盘上传阶段仍可能出现短时高速。

如需限制存储服务器的外网上传平均速度，请在 AList / OpenList 中设置「服务端上传限速」。这是存储服务的全局设置，会影响其他客户端上传，本程序不会自动改写。不同驱动的分片缓存方式不同，服务端限速也可能允许分片突发。

## 下载组件

共享下载限速需要支持 `--aria2c-rpc-config` 的 BBDown（bfb-2.0.8 起）。容器复用已有 aria2，由本程序管理其生命周期，不需要额外部署下载容器或开放控制端口。独立运行 BBDown 时可以继续使用原有命令行下载方式。
