# 兼容性边界

| 组件 | 当前范围 | 说明 |
| --- | --- | --- |
| 应用版本 | v2.5.2 | 文档只维护当前main稳定版 |
| Node.js | 24 | 源码运行要求`>=24 <25` |
| Docker平台 | `linux/amd64` | 当前工作流不发布ARM64 |
| BBDown | fork Release `bfb-2.0.4` | 固定源码提交，不跟随master；支持BFB结构化媒体探测 |
| FFmpeg | 固定Linux x64静态构建 | 镜像内同时提供ffprobe |
| aria2 | 镜像内安装 | 断点续传始终启用 |
| AList | Compose固定`v3.61.0` | 内置服务仍是 AList；外接实例不会自动升级，路径迁移依赖 WebDAV COPY |
| OpenList | 外接 WebDAV | 使用 OpenList 自己的镜像和数据目录；版本与挂载驱动由用户维护，路径迁移依赖 WebDAV COPY |
| 归档播放器 | MP4、M4V、WebM | 只播放远端已验证文件，不转码；编码兼容性取决于浏览器和设备 |

## AList / OpenList WebDAV

BFB依赖标准 WebDAV 行为，但不同网盘驱动在 PUT、MOVE、DELETE、文件大小和延迟可见方面可能不同。AList 与 OpenList 都可以作为外接 WebDAV 服务；普通新归档只要求目标目录可MKCOL、正式路径可PUT并能读取准确大小，不要求上传流程支持MOVE。项目固定内置 AList 版本不等于验证了每一种驱动，升级后应按[升级验收清单](../alist/upgrade)实测。

| WebDAV动作 | BFB用途 | 兼容边界 |
| --- | --- | --- |
| PROPFIND / stat | 目录扫描、文件大小确认、播放前核验 | 必须返回正确的文件类型和大小 |
| MKCOL | 创建上传和迁移目标目录 | 权限不足会阻止任务 |
| PUT | 上传视频、封面和元数据 | 普通新归档使用条件PUT避免覆盖竞态；某些驱动可能返回405但已经落盘，BFB会复核精确路径和大小 |
| GET / Range | 播放和断点读取 | 播放器需要存储端正确支持Range |
| MOVE | 画质替换、冲突历史归档、批量重命名和部分维护操作 | 普通新归档不依赖 MOVE；替换动作优先使用 MOVE，明确不支持时才检查 COPY |
| DELETE 文件 | 清理已确认文件 | BFB只删除已追踪文件，不递归删除未知文件 |
| COPY | 画质替换、冲突历史归档、批量重命名的安全回退，以及归档路径迁移 | 替换动作只有在 MOVE 明确不支持且 COPY 目标大小校验成功后才删除源文件；路径迁移仍在开始前独立探测 COPY，不支持时直接阻止迁移 |

### 通用兼容层的判断规则

- BFB只调用标准 WebDAV。AList、OpenList和其他兼容服务都经过同一层客户端、URL构造、目录条目解析和错误分类，不依赖私有 REST API。
- 远端文件核验始终显式区分 `exists`、`missing` 和 `unknown`。只有明确的 `404`、本地 `ENOENT/ENOTDIR`，或成功的目录列表中不存在唯一匹配，才允许进入缺失分支；`400/405/501`、权限、冲突、限流、5xx、超时和格式异常不能被当作缺失。
- 普通上传不会为了兼容性固定增加探测请求。目录缓存只在对应父目录发生PUT、COPY、MOVE或DELETE后失效；COPY/MOVE和扩展上传头的支持情况从真实操作中懒学习，并按后端身份隔离、限时保留。
- 文件名回退只在原路径被可靠确认未落盘后发生，别名使用稳定摘要避免重启后碰撞。结构化目录字段按字面解析，只有 `href` 进行一层URL解码；百分号字面量、Unicode NFC/NFD或多个物理命中不强行合并。
- 远端方法返回 `405/501` 时，播放的HEAD只回退一次一字节Range GET；上传扩展头只在可靠确认未写入时重试标准头。未知结果继续等待或进入人工恢复，不自动覆盖、删除或递归扫描。

截至 2026-08-15 的隔离探测：AList `v3.63.0` 天翼驱动 PUT 返回405但文件实际存在，COPY返回500；OpenList beta普通PUT、MOVE可用，但同一驱动COPY返回500。普通新归档只走正式路径PUT和大小确认，因此不要求MOVE；有完整旧证明的冲突归档会优先使用MOVE，COPY不可用或探测未知时保留冲突并等待人工处理。两者都应以你的版本、挂载和权限重新验证，BFB不会把未知COPY结果降级为本地下载再上传。

## B站接口

网页和APP播放接口都可能受账号权限、风控或上游变化影响。BFB只根据明确字段和稳定信号分类，不通过标题或错误文案猜测付费权限，也不会绕过B站限制。

`v2.5.2`沿用BBDown fork `bfb-2.0.4`。除既有PlayerUnite兼容外，BBDown提供BFB专用结构化媒体探测输出；BFB只把它作为可用组合和空间估算输入，最终下载仍以ffprobe实际媒体为准。

## 归档播放器

归档播放器读取的是已经上传并确认的 AList / OpenList 文件，不是B站在线流。默认优先透传远端提供的外部 HTTPS 临时直链，没有安全直链时由 BFB 代理单段字节范围请求；两种方式都要求存储端正确支持 Range。新下载保存 BBDown 实际选中的B站档位，实际画质和编码优先来自 ffprobe；播放器不展示请求配置，也不会根据分辨率猜B站档位。旧文件只有浏览器成功读取宽高后才会补齐，缺失的B站档位直接省略。H.264通常可直接播放；HEVC、AV1及特殊音轨是否可用取决于浏览器、操作系统和硬件解码能力。网络错误最多自动回退代理一次，解码错误不会回退，因为BFB不转码。MKV等未列入首版直播放范围的容器会保留归档，但不显示播放入口。

## 文件命名

旧命名文件只有在日期、分P、画质和编码资料可靠时才会自动预览重命名。多P身份无法确认、目标碰撞或扫描未完成时会跳过，不自动猜测。

## 已知依赖风险

当前根依赖生产审计报告11项风险（2项低危、3项中危、6项高危），涉及`axios`、`body-parser`、`brace-expansion`、`fast-xml-parser`和`ip-address`等传递依赖，其中部分问题暂无修复。项目不使用会破坏性降级主依赖的`npm audit fix --force`；部署仍应限制公网暴露并跟踪后续上游更新。文档站生产依赖当前为0项。
