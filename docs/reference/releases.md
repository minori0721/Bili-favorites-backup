## v2.6.2

### 本次更新

- 完成调度、存储和 HTTP 边界收口，保持现有接口、数据格式和操作流程不变。
- 区分下载证据缺失与损坏，阻止损坏清单被误用于上传、替换或自动清理。
- 按 B 站接口校验列表和分页响应，避免坏条目被当作空页、扫描完成或内容失效。

### 修复与保护

- 下载清单读取统一区分缺失、损坏和 I/O 失败；损坏原件备份失败时停止重建，不覆盖证据或删除媒体。
- 已有远端归档证明在本地清单损坏时继续保留，受影响条目停止上传、替换和自动清理并进入明确恢复流程；自动残片清理会跳过整个损坏目录。
- 收藏、收藏合集、追番追剧、稍后再看和历史列表分别校验实际字段与分页。合法空页和非视频历史记录继续支持，坏条目或分页使本页失败，不会触发假扫描完成或错误失效更新。
- 旧画质档案按分组隔离损坏记录，健康分组继续在事务内迁移；指定测试文件会规范化并去重，每个文件只执行一次。

### 架构与升级

- 应用入口只负责依赖组装、路由和生命周期；调度、同步、探测、传输、恢复和画质状态由对应工作流及窄接口持有。数据访问按领域仓储、查询投影和事务入口划分，架构检查持续限制跨层依赖和静默失败。
- 从 v2.6.1 升级无需新增配置或数据迁移；SQLite schema 11、JSON 状态 schema 13、迁移包 schema 3及存储键保持不变，保留原 `data`、`temp` 挂载。
- 更新后若提示下载证据损坏，应保留对应目录并按恢复提示重新探测。更新前备份数据目录并保留 v2.6.1 镜像摘要；回滚前确认没有未完成的导入、迁移或恢复操作。

## v2.6.1

### 本次更新

- 修复普通核验改变归档文件身份、导致播放链接和进度失效的问题。
- 完整恢复待核验任务，明确区分视频数、来源引用数与唯一路径数。
- 收紧外部响应、数据库恢复和持久化的失败边界，避免异常被误当作空数据或成功。

### 修复

- 普通核验、重试及说明更新保留远端文件 ID；显式新上传、已知大小改变或删除后重新登记时生成新身份，拒绝旧播放链接与迟到的媒体信息回报。
- 播放指纹不再依赖普通更新时间，并校验视频、路径、大小及上传证据；数据库替换后即使文件 ID 碰巧相同，也不会误接受不同文件的旧回报。
- 待核验分页先匹配真实来源再限制数量，视频级副本不再占用名额；启动恢复遍历全部分页，保留重试时间，不再受一万条上限截断。
- 归档导航分别显示按 BV 去重的视频数、来源文件引用数和唯一路径数。引用统计排除视频级副本、孤立记录和已完成删除的来源；全局路径独立去重，不累加账号统计。
- 搜索结果保持筛选后的视频统计口径，目录引用数不混入结果；数量描述本地登记状态，不代表实时远端盘点或文件存在证明。
- 区分 BBDown 探测及归档、播放、队列响应的非法数据与正常空结果，保留部分成功和错误信息；关键恢复、迁移与持久化失败继续向上传播。

### 内部维护

- 充电权限测试通过公开模块接口验证，保留事务、租约、代次及维护屏障；增加反静默失败架构检查与启动恢复失败边界测试。
- main 复用 dev 测试时核对同一提交、工作流版本及实际成功执行的测试步骤，保留可追溯证据；镜像构建与隔离启动验收始终执行。
- 来源引用统计集中到只读查询模块，补充真实 SQLite、响应契约与桌面/手机/横屏回归；保留现有两层记录和删除恢复算法，不迁移历史数据。

### 升级与回滚

- 从 v2.6.0 升级无需新增配置或数据库 schema 迁移，保留原 data、temp 挂载。源码部署须执行完整构建。
- 首次切换新播放指纹后，旧格式保存的播放进度无法自动沿用一次；视频文件、归档关系不受影响，无需重新下载。后续普通核验不会重置新进度。
- 更新前备份数据目录并保留旧镜像摘要；回滚前核实未完成的导入恢复操作，不删除持久恢复证据。

## v2.6.0

本版本对应前后端模块化重构及配套修复；`main` 构建通过后更新 `latest`，正式标签发布固定版本镜像 `v2.6.0`。

### 界面与归档

- 任务中心首屏直接显示看板加载结构，避免黑底日志闪现；按可用宽度显示四列、两列或单列，空队列收紧高度，有任务时保留列表内滚动。

- 修复归档导航对数字 UID 的校验错误，避免目录初始化失败后整个视频列表无法加载。此问题不涉及数据库丢失，不需要恢复备份或重建索引；更新镜像后刷新页面即可重新加载。
- 归档导航、分页、详情和播放数据在进入界面状态前校验；查询失败保留已有内容，取消或迟到响应不会覆盖新页面状态。

### 恢复与维护

- 恢复重下载不再因残留完成清单被误判为上传；提交失败保留原任务、会话和恢复证据，普通备份仍可复用有效本地成品。
- 会话失效统一停止请求、轮询、日志重连和播放器，并提供重新登录入口，不自动重放旧操作。
- 数据迁移新文件预览成功前禁止导入，关闭窗口取消旧请求；画质分批提交遇到失败时保留成功批次结果并停止后续提交。

### 开发与升级说明

- main 与已成功验收的 dev 为同一提交 SHA 时复用单元测试结果；版本、依赖、脚本或业务代码产生新提交后须先在 dev 验收。缺少成功记录时自动执行完整测试，镜像构建与隔离启动检查始终保留。

- 前端迁为严格 TypeScript 功能模块，新增内容哈希资源清单、开发监听和资源失败提示；调度器按扫描、探测、核验、恢复、画质与清理职责拆分，保持既有事务和维护屏障。
- 增加依赖边界检查、状态所有权文档，以及真实数据库响应经过 JSON 序列化再交给前端解析的回归，避免假服务数据与实际接口不一致。
- Docker 镜像从构建阶段复制完整资源及依赖，再裁剪开发依赖。沿用既有配置、接口、数据格式及挂载；手动部署源码时必须先执行完整 `npm run build`，不能只替换服务端文件。
- 更新前备份数据目录，保留旧镜像摘要；回滚前先确认没有未完成的导入恢复记录，参见[迁移与回滚](../operations/migration)。文档工具链的遗留依赖告警独立记录，本轮不升级整套依赖。
