# AList / OpenList 405

HTTP 405表示目标端拒绝当前 WebDAV 方法。它可能来自 AList / OpenList 驱动、反向代理方法限制、路径权限，也可能是上传会话在多文件过程中临时失效。

## 先看发生位置

- 首个文件 PUT 就405：更像驱动、权限或代理配置错误；如果驱动实际写入后才返回405，BFB会复核精确文件大小并确认已落盘。
- 首个文件 PUT 返回405、精确目标仍缺失但父目录可以列出：OpenList或挂载驱动可能只把底层原因压缩成通用405，例如单文件限制、驱动写入限制或最终一致性；BFB不会直接猜成大小限制。重复尝试后会在“待处理”显示“远端写入结果未确认”，保留本地文件并允许一次隔离媒体规格重试。父目录不可见、无法列出或权限/网络状态未知时不会提供这个入口。
- 同一任务已有文件成功，后续才405：当前批次会保留已写入结果和本地文件，随后进入远端确认；超过确认窗口后在队列提供“重新确认 / 继续上传”，不会由定时器自动重复PUT。
- MOVE返回405：不影响普通新归档；替换和批量重命名会在 MOVE 明确不支持、且 COPY 探测通过时使用 COPY+DELETE。路径迁移单独依赖 COPY，不能只根据 MOVE 的结果判断。
- DELETE返回405：新版和本地成品继续保留，画质清理持久重试。
- 归档来源删除期间其他账号仍可上传：这是来源级隔离的预期行为。被删除来源的上传、验证和质量替换会暂停，重启后也不会自动补回；如果只是远端返回405而没有确认删除，使用任务中的“重试”或重新预览，不要直接清空SQLite证明。

## 检查清单

1. 用同一 AList / OpenList WebDAV 账号在目标目录手动验证 PUT、精确路径大小确认和DELETE；替换或批量重命名时再验证 MOVE 和 COPY，路径迁移至少要验证 COPY。
2. 检查反向代理是否只允许GET/POST。
3. 确认 BFB 填写的是 WebDAV 可用的远端根地址和正确目标路径。
4. 查看 AList / OpenList 日志，区分服务本体、反向代理和网盘驱动返回。
5. 升级远端服务前备份数据，并按驱动重新做兼容性验收。

不要把所有405都当成网络超时，也不要把所有405都直接当成成功；只有精确路径的普通文件大小与本地文件一致，BFB才会确认上传。OpenList的通用405不足以证明具体驱动原因，更换画质或编码只是一次隔离验证，不保证解决权限或路径问题。大小冲突时不会自动覆盖旧文件；请先处理远端冲突，再使用“重新确认”或适用状态下的“继续上传”，也不要通过删除本地文件解除失败状态。

## 旧命名检查与预览凭证

“检查旧命名文件”先使用 SQLite 中已经验证的远端证明快速展示候选，同时在后台进行有界的远端深扫。深扫最多读取当前扫描上限对应的条目和目录；发现重复目录、格式异常、目录读取失败或达到边界时会标记为未完整覆盖。未完整结果不会把部分远端列表当成权威全量结果。

执行重命名前，服务端会创建一个短期预览会话。页面提交的是 `previewId` 和候选的 `candidateId`，不是远端路径；访问路径、预览时的大小和 OpenList 特殊字符访问写法由服务端保留。配置、命名规则、归档根或文件证明变化后，旧凭证会失效，需要重新预览。每个候选在 MOVE 或 COPY 前还会重新核验文件类型、大小、目录边界和目标冲突，因此不要复用旧页面或手工拼接请求。

轮询没有新 revision 时只返回扫描状态，页面会保留你已经取消的勾选；完整深扫完成后，远端已经不存在的本地候选会从可执行列表移除。在线内容的短期页面缓存也不会缓存归档状态，手动归档或恢复任务完成后，下一次打开页面会直接从 SQLite 刷新状态，不会额外请求 B 站。
