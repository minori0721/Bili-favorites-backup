# 远端延迟可见

上传完成后页面短时间显示“已上传·确认中”通常是正常状态。部分网盘在WebDAV PUT成功后不会立即通过目录列表或文件属性接口返回新文件。

## 正常行为

- BFB不重复PUT。
- 本地成品继续保留。
- 确认期间404不触发上传熔断。
- 远端同名同大小可见且Session保存了本次PUT证明后自动转为最终确认。

## 何时需要处理

超过确认窗口仍不可见时，任务会进入持久恢复状态。系统先按5分钟间隔低频只读复核；至少3次独立观察且从首次观察起持续30分钟仍不可见，才升级为需要关注的待处理项，之后继续使用30分钟、2小时或6小时的低频退避。文件已经出现、大小一致且持久Session记录了本次PUT时会自动确认；只有大小一致但没有PUT证明时仍视为来源未知，不会冒认成功。

本地文件组、上传Session和父目录均通过预检时，可选择“生成隔离候选”。该操作会额外占用远端空间和上传流量，但不会改动正式旧路径；多分P会整组进入同一个稳定候选目录。候选全部确认后，只有完整旧档与完整候选并存才会显示“保留现有归档 / 采用新候选”；旧档不完整或候选不完整时自动保留更完整的一份。认证失败、网络异常、父目录不可读或本地文件不完整时不会提供此写入动作。

如果本地待补传文件已经丢失或大小变化，系统会先检查全部正式远端文件：同大小则自动完成；全部缺失且原收藏来源仍有效时最多自动重新下载3次。达到上限后会停止自动循环并显示“重新下载”操作。该操作不会删除远端文件。

持续失败时检查：AList / OpenList 目录是否正确、账号能否 stat 精确路径、驱动是否返回真实文件大小，以及文件是否被网盘规则改名或移动。

## 不要把异常响应当作缺失

`400`、`405`、`409`、`412`、`429`、`5xx`、超时和目录清单格式异常只说明这次远端观察没有得到可靠结论，不表示文件已经消失。BFB会保留本地成品和已有远端证明，按错误类别退避；只有明确 `404`、`ENOENT`、`ENOTDIR`，或成功目录列表确认没有唯一匹配时，才进入缺失处理。

同一目录上传后，BFB只清除该父目录的短期列表缓存，后续确认仍使用精确路径和文件大小；不会为每个普通文件固定增加一次HEAD或PROPFIND。若服务端不支持HEAD，播放器只会在收到 `405/501` 后用一次 `GET Range: bytes=0-0` 读取响应头，不下载完整视频。

迁移包导入与路径预览/复制任务互斥。取消扫描后如果底层目录请求仍未返回，导入会等待有限时间；超时返回409，不会先替换SQLite再让旧Promise继续写入新库。路径迁移清理仍只按既有策略处理，BFB不会因为本次兼容层而递归删除未知目录内容。

远端显示未知同大小或同名异大小都属于冲突，不是可见性延迟。系统不会自动覆盖正式路径；人工恢复项由管理员确认生成候选并等待整组验证，完整旧档与完整候选并存时再选择保留哪一份。

## 播放信息仍显示未知

播放器中的“B站4K”来自BBDown当次实际选中的B站档位，不是根据像素尺寸推测；因此`1772×3840`可以同时显示为“B站4K · 实际1772p · 1772×3840 竖屏”。旧归档没有保存BBDown结果时不会补猜B站档位，支持当前编码的浏览器成功读取媒体信息后只会补齐宽高和时长。HEVC无法解码、文件加载失败或尚未播放时不会为了识别画质额外下载远端视频。

传输方式短暂显示“检测传输中”是播放器在等待当前请求结果；安全外部302会显示“网盘直连”，实际经过 Node 转发则显示“BFB代理”。最终错误时若仍无法确认会显示“传输方式未知”，不会把状态查询故障当作传输失败。网络错误会最多尝试一次代理；解码错误，尤其是浏览器不支持的 HEVC，不会通过代理重试，因为代理不能转码。如果是网络错误，优先检查 AList / OpenList WebDAV 下载、Range 和临时直链是否正常。
