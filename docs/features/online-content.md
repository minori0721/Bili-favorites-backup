# 在线内容与分层封面

“在线内容”是打开时读取 B 站的浏览工作区，和只读本地 SQLite 的“归档库”分开。它按账号提供在线收藏夹、订阅合集、追番、追剧、稍后再看和历史记录；关闭工作区后不会继续轮询这些页面。

在线条目只返回规范内容 ID、标题、UP 主、BVID 和脱敏状态，不把 Cookie、Token、签名播放地址或任意图片 URL交给前端。懒加载时每账号最多两个在线内容请求，缩略图请求全局合并并限制并发。

收藏夹导航会优先展示 B 站接口返回的收藏夹视频数量；打开分类后，页面响应提供可靠总数时也会显示当前分类总量。接口没有返回可靠数量时才显示“打开时加载”，不会用已加载的一页数量冒充全量数量。桌面端使用内容区关闭按钮，手机目录页使用侧栏关闭按钮，切换到内容页后关闭入口随工作区一起切换。

桌面端内容区的刷新与关闭操作固定在标题栏右侧，手机端仍按目录页/内容页分别显示返回和关闭入口；侧栏只显示“在线内容”标题，不重复展示读取策略说明。

## 手动归档

有规范 BVID 的在线视频可以选择“手动归档”。它会在当前账号下创建固定的“手动归档”来源，使用 `__BFB_MANUAL_<UID>` 保留目录段，并复用普通下载、上传、远端确认、冲突候选、恢复和删除引擎。重复点击、重启和同一 BVID 跨在线分类不会创建第二个来源。

追番季卡、直播、文章等没有规范 BVID 的条目只能打开 B 站；不能凭封面 URL猜测视频身份。已归档 BVID直接回到本地归档库，不建立重复手动任务。

## 封面生命周期

- `data/covers` 是归档封面，已有封面不会因为缓存上限或清理任务自动淘汰。视频失效后仍可显示。
- `data/online-covers` 是在线缩略图缓存，默认上限256MB，范围64MB至2GB，超过后按访问时间淘汰到90%水位。
- 在线条目有BVID时先复用归档封面，再查在线缓存，最后才请求图片。同一BVID跨账号和分类共用缓存键。
- “选择同步收藏夹”中的收藏夹封面也使用在线缩略图缓存：列表接口返回的封面会先作为提示写入缓存，只有提示缺失时才为可见收藏夹查询详情；之后直接读取`data/online-covers`，不重复请求B站。详情请求按账号限制并发，缓存缺失或被清理后才重新加载。
- 在线内容封面地址是受保护的短期引用，服务端有效期略长于图片响应的24小时缓存周期，支持卡片长时间懒加载；应用重启后重新打开工作区会生成新的引用。
- 手动归档时会优先把在线缩略图原子提升为归档封面；没有封面也不阻塞视频下载。
- “在线缩略图缓存”可以普通清理；“归档封面”清理需要输入 `DELETE ARCHIVE COVERS`，清理后SQLite中的本地封面路径会失效并允许重新回填。

迁移包默认包含归档封面，不包含在线缩略图；临时下载缓存的清理也不会触碰归档封面。
