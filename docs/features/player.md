# 归档播放器

BFB可以在收藏夹“查看详情”中直接播放AList里的已验证归档。点击可播放行或使用键盘`Enter`、`Space`即可打开；桌面端悬停或键盘聚焦时会显示播放标记，触屏设备不常驻显示遮罩。

也可以从[本地归档库](./archive-library)点击可播放卡片。此时播放器显示“归档库顺序”，并沿用打开时的账号、收藏夹、状态、标题排序和基础搜索上下文；播放器侧栏搜索只在这个上下文内进一步定位，清除后恢复原库队列。

## 可播放条件

播放器只接受以下内容：

- 收藏关系状态为“已备份”或“部分备份”。
- 远端文件已经通过BFB最终确认，而不是“上传确认中”。
- 文件容器为MP4、M4V或WebM。

待下载、待补传、上传确认中、远端缺失和下载失败项目不会开放流地址。历史关系可以从详情中单独播放，但不会进入当前收藏夹的连续队列。

## 顺序与分P

播放队列只包含当前仍在收藏夹中的可播放视频，顺序与收藏夹一致。多P优先使用归档时保存的分P序号；旧记录缺少序号时再解析文件名中的`_P<number>`，最后使用自然文件名顺序。

从归档库打开时，聚合目录会把同一BV合并为一个队列项，具体收藏夹则保留当前关系和历史关系顺序。系统会从该BV所有仍有效的归档证明中选择实际媒体参数更高、完整性更好的一份；未知实际参数不会仅凭下载目标获得更高优先级。当前来源失效后，手动重试会重新查询库队列。

默认会从当前分P继续到下一P，并在一条视频结束后进入收藏夹下一条可播放视频。可以在播放器中关闭“连续播放”。上一项、下一项、分P按钮和右侧编号队列都不会改变收藏夹或远端文件。

## 浏览与搜索

右侧队列每批从SQLite读取50项。滚到列表顶部或底部会继续读取相邻页面，因此收藏夹可播放视频不会被限制为50项；已加载页面会在本次播放器会话中缓存。从归档库打开时，相邻页面使用向前和向后的键集游标，焦点定位不会先给整个可播放库执行窗口排名；普通收藏夹播放器接口和数字分页兼容行为保持不变。

搜索框覆盖当前收藏夹全部可播放归档，可按视频标题、归档前标题、UP主或BV号查找。空格分隔的多个词需要同时匹配。搜索只负责定位：输入不会暂停当前视频，选择结果后会清空搜索并回到该视频在完整收藏夹中的位置，随后仍按原收藏顺序连续播放。

队列缩略图优先读取BFB本地封面缓存，失败后尝试原始封面，最终显示低对比度占位。封面使用固定尺寸和懒加载，不会在加载时改变队列行高。

## 横屏、竖屏与进度

播放器会根据媒体尺寸识别横屏或竖屏，始终使用完整显示，不裁切画面。桌面端显示播放器与编号队列；手机横屏继续使用横向播放器布局，支持设备自然旋转，不强制锁定方向。

宽度不超过720px的手机在竖屏方向默认使用“沉浸竖屏”：视频舞台占满当前视口，上滑依次进入下一P或收藏夹下一条可播放视频，下滑返回上一P或上一条。播放器进度条、设置、按钮和搜索输入不会触发滑动换集；横屏和竖屏归档都使用完整显示，不会为了填满屏幕裁切画面。

“列表”会从底部打开完整收藏夹队列和搜索，关闭后仍停留在当前播放视角。选择“普通”可以在当前浏览器关闭沉浸模式，普通布局中的“沉浸竖屏”按钮可重新开启；这个选择与音量、倍速等偏好一起保存在浏览器本地，不会修改服务端全局配置。设备转为横屏时会暂时恢复原布局，重新转回竖屏后继续采用保存的选择。

音量、静音、倍速、连续播放开关和分P进度保存在当前浏览器的本地存储中。进度每5秒以及暂停、关闭时保存，最多保留500条；距离开头不足10秒或距离结尾不足15秒的记录不会恢复。

## 字节流与安全

浏览器始终先请求BFB提供的受保护播放地址。BFB重新校验登录会话、账号、收藏夹、文件ID、关系状态和路径；AList返回不含凭据、非本机或私网的外部HTTPS临时直链时，BFB再用302让浏览器直接连接网盘，从而避免视频字节经过BFB服务器。

无法取得安全直链时会自动回退现有Node流代理。BFB不会让Node自动跟随远端跳转：AList内部跳转保留认证，跨源后立即移除认证，并逐跳限制为公开HTTPS地址；私网DNS、HTTP、循环跳转、异常端口和超过5跳的地址会被拒绝。直连和代理都保留单段`Range`、`HEAD`、`206 Partial Content`和`416 Range Not Satisfiable`，因此可以拖动进度。播放器确认网络或媒体来源错误时最多自动切换代理一次并恢复当前位置；确认是解码错误时不会重复传输相同文件。手动重试会生成新的播放尝试并重新获取临时直链。

默认设置为“优先网盘直连，失败自动代理”，也可在全局设置中改为“始终由BFB代理”。直连不会暴露AList地址、账号、密码或真实WebDAV路径，但网盘临时签名地址会在当前浏览器的网络面板中可见，且在过期前可能被直接访问。BFB不持久化或记录该地址。

播放器会在媒体信息末尾显示本次播放实际采用的“网盘直连”或“BFB代理”。这个结果来自当前播放请求，不是根据全局选项猜测；每次切换视频或分P都会重新判断，状态只在BFB进程内短期保留。状态查询暂时失败或10秒内没有得到结论时显示“传输方式未知”，不会把查询故障误报为视频传输失败。

## B站档位与实际媒体

设置中的画质和编码仍用于控制BBDown选择，但播放器不展示这些请求配置。新下载时，BFB从BBDown最终选择的`[视频]`结果保存真实B站档位，再由ffprobe记录成品宽高、帧率、时长和编码。播放信息按“P序号 · B站档位 · 实际画质 · 精确尺寸与方向 · 实际编码 · 传输方式”排列，例如`P1 · B站1080P60 · 实际1080p60 · 1080×1920 竖屏 · HEVC · 网盘直连`。

B站档位与像素尺寸是两件事：B站可以把`1772×3840`归入4K档，因此会显示`P1 · B站4K · 实际1772p · 1772×3840 竖屏 · HEVC · 网盘直连`。实际画质标签直接采用真实短边，帧率不低于50时追加`60`，不会按常见档位向上或向下猜测。

旧归档不会批量读取几千个远端视频。浏览器首次成功读取某个旧文件时，只把实际宽高和时长连同当前文件fingerprint回报给BFB；浏览器不能声明B站档位、编码或帧率，也不能覆盖已有ffprobe结果。旧记录没有BBDown选择结果时直接省略“B站…”段，无法确认的实际参数显示未知。

## 在AList中查看

在全局设置中填写独立的“AList网页访问地址”后，播放信息末尾会出现“在 AList 中查看”。该地址可以是AList根地址，也可以包含反向代理基础路径；BFB会重新校验文件归属和确认状态，再在新标签页打开对应路径。

网页访问地址与容器内部WebDAV通信地址互相独立。未配置时入口不显示；AList需要登录时由AList自己处理。建议使用HTTPS，文件路径会按正常网页导航出现在新标签页地址栏中。

## 编码兼容性

BFB不转码。H.264通常能在现代浏览器中直接播放；HEVC、AV1及特殊音轨取决于设备、操作系统和浏览器的原生解码支持。播放器只把ffprobe确认的值显示为实际编码；旧记录缺少实际编码时不会把下载编码偏好显示出来，但仍可在浏览器明确不支持HEVC时用它给出保守兼容提示。实际或高度疑似HEVC且浏览器未报告支持时不会切换代理，因为代理只搬运相同字节、不能改变编码。可尝试支持HEVC的Edge、Safari、系统浏览器或AList客户端，也可以在队列中跳过该视频。

播放器读取远端归档，不解析B站在线流，不会绕过B站账号权限或地区限制。
