# 本地归档库

“归档库”位于账号与同步区域的“全量扫描并对账”右侧。它是BFB本地索引的只读媒体库，不是B站在线收藏夹页面：打开目录、搜索和翻页只读取`data/bfb.sqlite`与当前账号配置，不临时请求B站，也不列出AList目录。

## 目录范围

左侧目录固定包含：

- **全部归档**：当前配置中所有账号的本地关系，按BV号合并。
- **该账号全部**：只聚合一个账号，重复BV仍只显示一次。
- **当前同步收藏夹**：保留B站收藏顺序，已经移出的历史关系放在当前关系之后。
- **已停用归档**：SQLite仍有关系、但当前不再选择同步的收藏夹，只读折叠显示。

已选择但尚未扫描的收藏夹也会出现，并标记“暂无本地索引”。删除账号配置后，该账号不再属于当前归档库授权范围；迁移或恢复数据时应同时保留相应账号配置。

桌面端采用左侧目录与右侧封面网格的全屏工作区。手机先显示带封面摘要的目录，再进入两列视频网格；返回目录和关闭工作区都会保留适用的滚动位置。浏览偏好只在当前浏览器保存目录、筛选、排序和滚动位置，不保存搜索词。

## 搜索、筛选与排序

每批最多读取50个BV，滚到底部后继续追加，不会清空已加载卡片。搜索覆盖当前保存的标题、归档前标题、UP主和BV号；空格分隔的多个词采用AND匹配，`%`和`_`按普通字符处理。

搜索默认限制在当前目录，也可以切换为跨账号“全部归档”。状态筛选含义如下：

| 筛选 | 含义 |
| --- | --- |
| 全部 | 当前范围内所有本地关系 |
| 可播放 | 至少有一份可直接播放的已验证成品 |
| 待处理 | 没有可播放成品，但仍在发现、排队、下载、上传或远端确认阶段 |
| 异常 | 没有可播放成品，且当前为失败、远端缺失、充电限制、失效或无兼容媒体 |

具体收藏夹的默认顺序是当前关系按收藏顺序在前，历史关系按最后发现时间倒序在后。账号与全局聚合默认按BV最近一次发现时间倒序；也可以按归档标题正序或倒序。

## 卡片与来源

卡片封面优先使用BFB本地缓存，失败后尝试SQLite保存的原始封面，最终显示固定占位。卡片同时显示归档前标题、UP主、BV号、状态、分P或已确认实际画质，以及最多三个收藏夹来源摘要。

聚合范围内同一BV只显示一次，但不会合并或删除底层收藏关系。不可播放卡片打开来源详情，列出账号、收藏夹、当前或历史关系、最后发现时间和脱敏错误摘要；响应不会包含AList真实路径、账号密码、B站Cookie或网盘签名地址。

## 从归档库播放

可播放卡片直接进入现有归档播放器。连续队列沿用打开时的目录、基础搜索、状态和标题排序，并自动跳过不可播放项目。播放器中的搜索只进一步过滤这个库上下文，清除后恢复原库队列。

同一BV存在多份已验证成品时，BFB依次比较：

1. 所有分P都已有实际尺寸时，最低短边更高者优先。
2. 实际帧率更高者优先。
3. 完整备份优先于部分备份。
4. 已验证分P更多者优先。
5. 最近确认者优先，最后使用稳定来源键打破平局。

实际参数未知的来源不会因为下载时请求了4K或HEVC而冒充更高质量。播放流、302直连、BFB代理、Range、媒体元数据回报和AList网页入口仍使用原有文件归属校验；当前来源失效后，手动重试会重新查询队列并允许选择其他仍有效来源。

## 功能边界

第一版归档库不提供删除、移动、重新扫描、勾选同步或对账操作，也不包含B站“收藏的合集/订阅合集”。它展示的是BFB已经保存的本地证据；需要更新在线收藏状态时仍应使用正常同步或“全量扫描并对账”。
