# 本地归档库

“归档库”位于账号与同步区域的“全量扫描并对账”右侧。它不是B站在线收藏夹页面：打开目录、搜索和翻页只读取`data/bfb.sqlite`与当前账号配置，不临时请求B站，也不列出 AList / OpenList 目录。只有用户明确发起来源删除时，BFB才按持久清单访问远端存储核验和删除文件。

## 目录范围

左侧目录固定包含：

- **全部归档**：当前配置中所有账号的本地关系，按BV号合并。
- **该账号全部**：只聚合一个账号，重复BV仍只显示一次。
- **当前同步收藏夹**：保留B站收藏顺序，已经移出的历史关系放在当前关系之后。
- **已停用归档**：SQLite仍有关系、但当前不再选择同步的收藏夹，只读折叠显示。
- **已移除账号**：账号登录信息已经移除，但本地证明和归档仍保留；同一UID重新登录后会恢复为当前账号。

已选择但尚未扫描的收藏夹也会出现，并标记“暂无本地索引”。仅移除账号登录不会删除B站Cookie之外的归档索引，已移除账号仍可搜索和播放；账号快照只保存UID、名称、头像和移除时间，不保存Cookie、Token或APP身份。

桌面端采用左侧目录与右侧封面网格的全屏工作区。手机先显示带封面摘要的目录，再进入两列视频网格；返回目录和关闭工作区都会保留适用的滚动位置。浏览偏好只在当前浏览器保存目录、筛选、排序和滚动位置，不保存搜索词。

## 搜索、筛选与排序

每批最多读取50个BV，滚到底部后继续追加，不会清空已加载卡片。搜索覆盖当前保存的标题、归档前标题、UP主和BV号；空格分隔的多个词采用AND匹配，`%`和`_`按普通字符处理。

搜索默认限制在当前目录，也可以切换为跨账号“全部归档”。状态筛选含义如下：

| 筛选 | 含义 |
| --- | --- |
| 全部 | 当前范围内所有本地关系 |
| 可播放 | 至少有一份可直接播放的已验证成品 |
| 待处理 | 没有可播放成品，但仍在发现、排队、下载、上传或远端确认阶段 |
| 异常 | 没有可播放成品，且当前为失败、远端缺失、充电限制、失效或无兼容媒体 |
| 已删除 | 只显示手动删除留痕，不进入普通搜索或播放队列 |

具体收藏夹的默认顺序是当前关系按收藏顺序在前，历史关系按最后发现时间倒序在后。账号与全局聚合默认按BV最近一次发现时间倒序；也可以按归档标题正序或倒序。

全局和账号聚合使用SQLite schema 8中的持久投影完成搜索、筛选和稳定分页；`v2.5.0`数据库还包含schema 9的持久上传会话与逐文件状态以及schema 10的上传代际。收藏关系、远端证明或手动删除状态变化时，BFB只刷新受影响的BV；具体收藏夹不使用聚合投影，仍直接读取实时关系以保留B站收藏顺序。首次从schema 7升级时会在一个事务内构建完整投影，因此大库第一次启动会比平时更久，后续浏览不会重复全库构建。

## 卡片与来源

卡片封面优先使用BFB本地缓存，失败后尝试SQLite保存的原始封面，最终显示固定占位。卡片同时显示归档前标题、UP主、BV号、状态、分P或已确认实际画质，以及最多三个收藏夹来源摘要。

聚合范围内同一BV只显示一次，但不会合并或删除底层收藏关系。不可播放卡片打开来源详情，列出账号、收藏夹、当前或历史关系、最后发现时间和脱敏错误摘要；响应不会包含 AList / OpenList 真实路径、账号密码、B站Cookie或网盘签名地址。

## 从归档库播放

可播放卡片直接进入现有归档播放器。连续队列沿用打开时的目录、基础搜索、状态和标题排序，并自动跳过不可播放项目。播放器中的搜索只进一步过滤这个库上下文，清除后恢复原库队列。打开焦点视频时只统计其排序键之前的可播放数量并读取当前页，向前或向后滚动再通过键集游标加载相邻页，不会先对整个库队列执行窗口排名。

同一BV存在多份已验证成品时，BFB依次比较：

1. 所有分P都已有实际尺寸时，最低短边更高者优先。
2. 实际帧率更高者优先。
3. 完整备份优先于部分备份。
4. 已验证分P更多者优先。
5. 最近确认者优先，最后使用稳定来源键打破平局。

实际参数未知的来源不会因为下载时请求了4K或HEVC而冒充更高质量。播放流、302直连、BFB代理、Range、媒体元数据回报和 AList / OpenList 网页入口仍使用原有文件归属校验；当前来源失效后，手动重试会重新查询队列并允许选择其他仍有效来源。

## 删除具体来源

卡片的更多操作会打开来源详情。以下来源允许删除：

- 已移出当前收藏夹的历史关系。
- 已停用收藏夹中的来源。
- 已移除账号保留的来源。

当前仍在同步且仍属于收藏夹的关系禁止删除，否则下一次同步会再次归档。第一版一次只删除一个具体来源，不提供“删除全部来源”。预览会显示已追踪文件数、空间和共享文件数；输入`DELETE ARCHIVE`后任务开始，任务不可取消。

BFB会先对全部候选执行HEAD预检，确认来源仍可删除、文件位于当前`alistDest`边界内、类型和大小与SQLite证明一致且没有关联任务占用。任何冲突都会阻止整项删除。物理路径仍被其他来源引用时只解除当前来源证明；404视为已删除。BFB不会对远端目录发送集合`DELETE`，因此未知文件不会被目录清理连带删除；任务完成后可能留下空目录，可在 AList / OpenList 中人工确认后处理。

任务使用 SQLite 租约和逐文件进度，容器重启后从最后确认项继续。401、403、路径或大小冲突会等待人工处理；超时和5xx经过1分钟、10分钟、1小时退避后转为手动重试。远端连接、归档路径或本地证明已经变化时，请使用“重新预览并确认”，旧失败记录仍保留作审计。

清理完成后，目标来源从普通列表、搜索、远端验证和播放队列排除；如果同一BV还有其他成品，卡片会自动切换到最佳来源。没有其他来源时只在“已删除”筛选保留标题、封面、来源、删除时间、文件数和空间。以后视频重新加入活动收藏夹时，删除留痕会转为恢复状态并按正常流程重新归档，不形成永久排除。

## 功能边界

第一版归档库不提供移动、重新扫描、勾选同步、对账或批量删除全部来源，也不包含B站“收藏的合集/订阅合集”。需要更新在线收藏状态时仍应使用正常同步或“全量扫描并对账”。
