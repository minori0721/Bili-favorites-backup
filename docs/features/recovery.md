# 异常熔断与恢复

## 已归档内容的失效筛选

收藏夹详情的“已上传且失效”包含已上传、已验证或部分已验证的来源中，当前收藏关系标记失效或B站详情确认不可用的条目。本人可见和手动来源不因收藏夹标记进入此筛选；其他收藏夹的失效标记不会直接扩散到当前关系。

“收藏夹标记失效”不代表确认删除。条目分别显示收藏夹证据和详情确认，已有可播放归档仍可播放。按钮名称保持不变，计数和分页使用相同条件。

筛选只展示已有记录，已有归档继续保留。需要检查源站当前状态时可点击“立即复核”；正常同步确认收藏恢复可用后，条目会退出失效筛选。

手动画质与编码探测遇到临时详情错误时显示“暂时无法确认B站源状态”，不会宣称视频已删除或不可见；只有明确不可用才显示相应提示。

## 互动视频解析失败

互动视频需要完整的可达剧情清单。BFB通过 BBDown 获取清单，下载前再次核对；剧情变化时先停止这次下载，再按新清单恢复。

已验证的本地片段继续保留，只补缺失片段；全部片段校验完成后才能正常完成下载。媒体探测也核对完整清单，不能把跳过片段的大小当成总大小。现有严格编码和画质校验继续生效，不改变WebDAV或旧档保护流程。

剧情接口超时、权限错误、限流、格式异常或超过500节点/5000选择/90秒预算时，返回剧情解析错误，不据此判定视频删除。没有完整清单时不启动下载；先解决工具或接口问题再重试，不需要因这类错误更换编码。

镜像内置的 BBDown `bfb-2.0.7` 支持完整剧情清单协议。使用自定义旧工具时，缺少协议会提示解析失败；恢复下载仍需 B站提供对应片段的可下载媒体流。普通视频使用原有下载流程。

## 本地文件保留

停止状态优先于旧的人工处理标记。已停止尝试不会出现在待处理或上传看板，也不会被后台恢复重新领取；启动和数据库重载会修正历史矛盾标记，周期恢复每批最多修正1000条。任务历史、分P证据和文件记录继续保留。用户主动创建的新尝试不继承旧代停止状态。

本地文件缺失且B站源不可用时，由低频可用性探测等待源恢复，不以旧上传任务反复重试。历史停止标记不能证明用户亲自删除过文件。

“停止本次尝试”会停止自动执行，保留本地成品和远端文件。本地文件仍计入缓存占用，可以在归档详情中预览并决定是否释放空间。

远端只读确认不需要本地视频存在，但必须使用当前传输代次的证据。旧代成功不能标记新代成功；空代次只能在核验旧档后结束，不能借用旧代分P。

上传完成后的本地清理会独立重试，容器重启后继续核对和收尾。文件仍被其他任务使用或已发生变化时会保留，不会重新上传已经完成的文件。

归档详情中的“释放本地空间”会先预览文件及已有归档情况；仍有传输任务时，须先停止本次尝试。确认删除需要输入 `DELETE LOCAL`。本地文件可能是唯一副本，也可能与其他归档版本不同，请按预览结果决定是否保留。文件在预览后变化时需重新核对；只处理这次确认的文件，无法识别的文件继续保留。

BFB把B站下载接口健康和 AList / OpenList WebDAV 上传健康分开管理。任一侧异常时只暂停会扩大故障的工作，已经拿到下载地址的 aria2 传输不会被无关熔断中断。

待处理中心只显示需要管理员决定的事项。没有这类事项时，中心会直接显示空状态，不额外占用一行“自动复核中”提示；后台复核仍会继续运行，新的人工事项出现后才会重新显示摘要。

## 远端 WebDAV 异常

认证、权限、驱动或持续网络故障会触发上传熔断，并暂停启动新下载，避免本地缓存持续堆积。失败流程不会因上传后端异常主动清理待补传本地文件；远端后端恢复后由持久补传流程继续。

单个确定性失败会隔离到自己的补传任务，不会永远卡住其他视频。AList / OpenList 返回405时，BFB会先复核文件是否已经按预期大小落盘：落盘一致才确认成功，否则根据发生阶段区分临时上传会话异常和真实驱动错误。

认证、权限或地址异常时，“检查存储配置”会回到全局设置并聚焦“只读检查存储连接”。检查最多等待15秒，只读取当前草稿配置对应的端点与目录。修改配置后需保存，写入权限可通过归档一个小视频确认。

## 什么时候需要选择

- 远端暂时不可见会先自动复核；至少3次独立观察且持续30分钟后才进入人工待处理。
- 未知同大小、异大小或多分P混合状态不会覆盖正式路径。异大小冲突、多分P混合状态以及达到3次/30分钟门槛的长时间不可见，会在本地整组文件和候选父目录安全时自动生成`_conflicts`候选；只有完整旧档和完整候选并存时才再选择保留哪一份。候选本身失败后会停止自动生成，回到待处理中心，避免重复创建远端副本。
- 可恢复的下载达到重试上限后，可继续当前账号、先验证另一个已登录账号，或暂缓24小时。明确下架或不可用不会伪装成普通重试任务：收藏夹首次报告失效时先进入待确认，两个详情接口都给出明确不存在证据后才停止当前下载，并按1天、7天、30天低频复核，之后每30天继续复核，直到不再需要补档。旧版本已休眠的未归档视频会在启动时分散到后续30天复核；既有待复核任务的到期时间和轮次保持不变。视频源状态不会删除或改写已有归档证明和封面记录。
- 视频详情的临时超时、5xx、未知业务码或空分P只表示“暂时无法确认”，按10分钟、1小时、6小时、24小时、7天退避，此后每7天继续复核，不会被猜成已删除。视频源状态不会进入待处理角标；详情中的“立即复核”只唤醒同一个持久探测任务，没有可用账号时会提示先登录或启用账号。
- 画质重调只有在失败发生于下载或暂存上传、证据明确指向媒体规格/单文件限制且正式替换尚未开始时，才允许重新选择画质与编码生成独立版本。选择器先列出所有分P共同可用的组合和预计空间；替换和旧文件清理失败只恢复原阶段。

严格媒体重试会逐分P核对所选画质和实际编码。未达到要求或无法确认时，候选回到待处理，原归档和本地原文件继续保留。

这些操作都不会修改全局编码偏好。旧档不完整时自动采用已验证候选，候选不完整时自动保留完整旧档；完整旧档与完整新候选仍由用户选择，另一份远端文件不会自动删除。

自动复核逐个视频进行，探测请求至少间隔10秒。普通复核使用 UP 授权账号和活动收藏关联账号；充电权限复核还会检查其他启用账号。没有相关可用账号时，按提示登录或启用账号；取得有效详情后继续补档。

已经有已验证归档的视频，收藏夹报告失效后不自动增加长期探测。页面显示归档结果和源站状态，不再把这种情况描述成正在后台复核；已有归档与封面继续保留。

源站原因按接口结果展示：62004为“审核中”，62012为“仅UP主自己可见”，62002为“稿件不可见，具体原因未公开”，-404为“B站未找到该视频”。后两者只能说明这次查询不可用。审核中和仅UP主可见仍按未知状态定期复核，相关账号取得有效分P后恢复归档；结果冲突或包含临时错误时显示通用未知原因。

路径迁移弹窗中的“查看冲突与失败项目”按需分页读取已有记录，可查看相对路径、源大小和错误原因。目标大小未记录时明确标示，不额外请求远端；核对存储端冲突或更换目标目录后重新预览。关闭弹窗只停止页面轮询，不停止后台迁移。

## B站风控

网页接口收到`v_voucher`稳定信号后：

1. 保留下载会话和已完成内容。
2. 全局停止启动新BBDown任务3分钟。
3. 冷却结束只放行原失败任务探测。
4. 有APP token时临时用APP接口；没有则继续Web单任务探测。
5. 收到播放地址就恢复健康，不等待整段视频下载结束。

探测再次触发风控会重新冷却固定3分钟，不指数延长。用户选择常驻APP模式时，所有新任务使用APP接口。

启动和周期复核会自动补齐尚未完成的上传确认任务。多分P候选显示已确认数量，已确认分P保持原样，其余继续恢复。

“放弃本次候选”会停止该候选的排队和提示，保留本地、远端文件及处理记录。以后视频再次需要归档时，可以建立新的尝试。

## 容器重启

SQLite任务、冷却截止时间和下载会话都持久化。异常退出依靠任务租约过期恢复；正常SIGTERM/SIGINT会停止领取任务、终止BBDown/aria2并等待最多20秒落盘。
