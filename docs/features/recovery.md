# 异常熔断与恢复

## 互动视频解析失败（开发中）

互动视频的普通详情可能只包含根片段；它不等于完整剧情清单。开发分支先由BBDown获取接口返回的可达剧情，按CID去重后建立下载清单；下载前再次比较CID顺序摘要，发生变化时停止，避免分P编号对应错误。此摘要不是视频内容哈希。

已验证的本地片段继续保留，只补缺失片段；全部片段校验完成后才能正常完成下载。媒体探测也核对完整清单，不能把跳过片段的大小当成总大小。现有严格编码和画质校验继续生效，不改变WebDAV或旧档保护流程。

剧情接口超时、权限错误、限流、格式异常或超过500节点/5000选择/90秒预算时，返回剧情解析错误，不据此判定视频删除。没有完整清单时不启动下载；先解决工具或接口问题再重试，不需要因这类错误更换编码。

`v2.5.5`已固定到发布版`bfb-2.0.5`及其ZIP校验值；`bfb-2.0.4`不支持新协议，自定义旧工具会安全失败。普通视频不增加剧情请求；账号、接口和运行配置相同时保留`2.0.4/2.0.3`续传轨道，配置变化仍按原规则隔离。本轮不还原互动玩法、条件变量或隐藏剧情，不承诺B站一定提供所有片段的下载流，也未修改线上失败任务。

## 开发分支的本地文件保留

停止状态优先于旧的人工处理标记。已停止尝试不会出现在待处理或上传看板，也不会被后台恢复重新领取；启动和数据库重载会修正历史矛盾标记，周期恢复每批最多修正1000条。任务历史、分P证据和文件记录继续保留。用户主动创建的新尝试不继承旧代停止状态。

本地文件缺失且B站源不可用时，由低频可用性探测等待源恢复，不以旧上传任务反复重试。历史停止标记不能证明用户亲自删除过文件。

“停止本次尝试”仅停止自动执行，不删除本地成品或远端文件。上传失败、严格规格不匹配和视频源不可用，不代表已有本地文件失去保存价值；保留文件仍会占用缓存空间。

远端只读确认不需要本地视频存在，但必须使用当前传输代次的证据。旧代成功不能标记新代成功；空代次只能在核验旧档后结束，不能借用旧代分P。

清理授权保存在原有任务JSON中，逐文件绑定下载清单、传输代次、大小与文件身份。上传业务完成不等于清理完成：尚未清理的授权在重启后继续核对，但不再作为上传任务领取，也不阻止新的归档尝试。出现新任务引用、同大小文件替换或代次变化时保留本地文件；没有授权时不因同BV存在其他归档而清理。

归档详情提供“释放本地空间”危险操作。已有成功清理授权的文件会再次核对远端证明；失败或停止后保留的文件也可预览，但必须输入 `DELETE LOCAL` 明确确认删除。界面说明是否存在已验证归档；没有证明时，本地文件可能是唯一副本。即便已有其他归档，也不保证与本次文件是同一版本。仍有传输任务时须先停止本次尝试。预览绑定下载清单、传输代次和文件身份，变化时拒绝删除，未知文件保留。该操作不授权后续自动删除其他文件。历史文件缺失与停止标记也不能单独证明具体删除原因。

BFB把B站下载接口健康和 AList / OpenList WebDAV 上传健康分开管理。任一侧异常时只暂停会扩大故障的工作，已经拿到下载地址的 aria2 传输不会被无关熔断中断。

待处理中心只显示需要管理员决定的事项。没有这类事项时，中心会直接显示空状态，不额外占用一行“自动复核中”提示；后台复核仍会继续运行，新的人工事项出现后才会重新显示摘要。

## 远端 WebDAV 异常

认证、权限、驱动或持续网络故障会触发上传熔断，并暂停启动新下载，避免本地缓存持续堆积。失败流程不会因上传后端异常主动清理待补传本地文件；远端后端恢复后由持久补传流程继续。

单个确定性失败会隔离到自己的补传任务，不会永远卡住其他视频。AList / OpenList 返回405时，BFB会先复核文件是否已经按预期大小落盘：落盘一致才确认成功，否则根据发生阶段区分临时上传会话异常和真实驱动错误。

认证、权限或地址异常时，“检查存储配置”会回到全局设置并聚焦“只读检查存储连接”。该检查使用当前草稿，最多等待15秒，只读取WebDAV端点和归档目录，不保存配置、不写测试文件，也不承诺账号具备写入权限。

## 什么时候需要选择

- 远端暂时不可见会先自动复核；至少3次独立观察且持续30分钟后才进入人工待处理。
- 未知同大小、异大小或多分P混合状态不会覆盖正式路径。异大小冲突、多分P混合状态以及达到3次/30分钟门槛的长时间不可见，会在本地整组文件和候选父目录安全时自动生成`_conflicts`候选；只有完整旧档和完整候选并存时才再选择保留哪一份。候选本身失败后会停止自动生成，回到待处理中心，避免重复创建远端副本。
- 可恢复的下载达到重试上限后，可继续当前账号、先验证另一个已登录账号，或暂缓24小时。明确下架或不可用不会伪装成普通重试任务：收藏夹首次报告失效时先进入待确认，两个详情接口都给出明确不存在证据后才停止当前下载，并按1天、7天、30天低频复核后休眠。休眠不要求人工放弃；收藏夹重新可见或相关账号重新登录后会自动唤醒。视频源状态不会删除或改写已有归档证明和封面记录。
- 视频详情的临时超时、5xx、未知业务码或空分P只表示“暂时无法确认”，按10分钟、1小时、6小时、24小时、7天退避后休眠，不会被猜成已删除。视频源状态不会进入待处理角标；详情中的“立即复核”只唤醒同一个持久探测任务，没有可用账号时会提示先登录或启用账号。
- 画质重调只有在失败发生于下载或暂存上传、证据明确指向媒体规格/单文件限制且正式替换尚未开始时，才允许重新选择画质与编码生成独立版本。选择器先列出所有分P共同可用的组合和预计空间；替换和旧文件清理失败只恢复原阶段。

严格媒体重试不会把 BBDown 的“已选择流”日志当成成功证明。选择行只用于在明确选中错误档位或编码时提前停止；B站画质档位由持久下载清单逐分P核对，实际编码最终由每个分P的 `ffprobe` 决定。调度器创建上传任务前，以及 `UploadTask` 发出第一条 WebDAV 请求前也会再次核验。请求规格不匹配或证明无法确认时，候选保持失败并进入待处理；原归档证明和收藏关系不变，该失败流程也不会主动清理本地原文件。

这些操作都不会修改全局编码偏好。旧档不完整时自动采用已验证候选，候选不完整时自动保留完整旧档；完整旧档与完整新候选仍由用户选择，另一份远端文件不会自动删除。

![B站播放接口触发风控后的三分钟冷却](/screenshots/download-risk.png){.doc-shot}

`access_probe`从持久状态恢复时按BVID去重；同一计划重复执行启动补偿不会生成第二个探测任务。普通来源复核仅尝试UP主账号和活动收藏关联账号，并按实际UID去重；充电复核才继续检查其他启用账号。手动复核没有相关可用账号时提示登录或启用相应账号，不尝试无关账号。

已经有已验证归档的视频，收藏夹报告失效后不自动增加长期探测。页面显示归档结果和源站状态，不再把这种情况描述成正在后台复核；已有归档与封面继续保留。

源站原因只按实际接口证据展示：62004为“审核中”，62012为“仅UP主自己可见”，62002为“稿件不可见，具体原因未公开”，-404为“B站未找到该视频”。后两者不能证明作者永久删除了视频。审核中和仅UP主可见仍归为未知状态，沿用10分钟、1小时、6小时、1天、7天的原有退避及休眠规则；任一相关账号取得有效分P仍按原流程恢复。多个未知结果互相矛盾或含临时错误时，保留通用未知原因，不猜测审核或隐私状态。本次不新增详情接口，不读取投稿管理接口，也不批量重置历史探测。

路径迁移弹窗中的“查看冲突与失败项目”按需分页读取已有记录，可查看相对路径、源大小和错误原因。目标大小未记录时明确标示，不额外请求远端；核对存储端冲突或更换目标目录后重新预览。关闭弹窗只停止页面轮询，不停止后台迁移。

## B站风控

网页接口收到`v_voucher`稳定信号后：

1. 保留下载会话和已完成内容。
2. 全局停止启动新BBDown任务3分钟。
3. 冷却结束只放行原失败任务探测。
4. 有APP token时临时用APP接口；没有则继续Web单任务探测。
5. 收到播放地址就恢复健康，不等待整段视频下载结束。

探测再次触发风控会重新冷却固定3分钟，不指数延长。用户选择常驻APP模式时，所有新任务使用APP接口。

启动、数据库重新绑定、周期复核和打开待处理中心会检查现有上传会话是否缺少对应任务，并按`sessionId + generation`补建唯一恢复任务。该投影仍使用现有`jobs`表，不创建第二套任务系统；已验证或已替代的会话不会重新出现。

恢复投影按页读取传输会话，不会因为前面的活动任务很多就永远漏掉后面的孤儿会话。多分P候选会明确显示“部分分P”和已确认数量；已确认分P不会重复上传，剩余分P在同一候选代次中继续恢复。页面投影只读取SQLite，不同步阻塞检查本地视频文件，真正执行恢复前才做本地清单、大小和证明复核。

待处理中的候选可以选择“放弃本次候选”。这个动作只结束当前候选的调度生命周期并保留审计信息；它不会删除本地文件、隔离远端文件或原归档证明，也不会自动删除任何远端文件。已放弃候选不会在每轮同步中重新刷出；以后视频再次需要归档时仍会创建新的候选代次。旧版下载失败也会投影到同一个待处理中心，只有用户明确放弃后才停止继续提示。

## 容器重启

SQLite任务、冷却截止时间和下载会话都持久化。异常退出依靠任务租约过期恢复；正常SIGTERM/SIGINT会停止领取任务、终止BBDown/aria2并等待最多20秒落盘。
