# 整体运行流程

BFB把一次备份拆成可以独立恢复的阶段。下载成功、上传返回201和最终备份完成是三个不同状态。

<div class="workflow-line">
  <span>扫描收藏夹</span><i>→</i><span>权限判定</span><i>→</i><span>下载与验证</span><i>→</i><span>上传</span><i>→</i><span>远端确认</span><i>→</i><span>安全清理</span>
</div>

## 1. 扫描收藏夹

系统先扫热点页，再逐步补扫历史页。每个视频与“账号 + 收藏夹”的关系分别保存，避免同一个BV出现在多个收藏夹时漏传目标目录。

## 2. 权限判定

下载前先获取视频详情。明确下架转为失效；充电专属且无完整权限转为七日复查；临时风控进入冷却，不会立即循环启动BBDown。

## 3. 下载与本地验证

BBDown固定使用项目fork Release，aria2负责字节级续传。分P以CID识别，媒体文件还需通过大小、时长、流信息与分P覆盖检查，只有完整成品可以上传。

## 4. 上传与远端确认

上传前先整组检查旧归档证明和全部分P目标。当前来源已有完整且远端一致的旧证明时保留旧档并跳过新版；没有旧证明的普通新归档直接条件PUT到正式路径，不创建暂存目录，也不依赖MOVE。未知同大小、异大小、部分旧证明或证明漂移时，完整新文件组PUT到独立`_conflicts`候选目录，正式旧路径保持不变，等待管理员选择。画质替换和远程重命名继续独立探测 MOVE/COPY，按各自的显式替换规则执行。

## 5. 清理

所有最新版目标和历史文件均已确认后，系统只删除下载会话清单内的本地文件。无法识别的残片不会自动删除，只会进入清理预览。

## 6. 浏览本地归档库

账号与同步区域提供独立的全屏归档库。它只读取 SQLite 和当前账号配置，按全局、账号、当前收藏夹或已停用收藏夹浏览，不会为了翻页或搜索请求B站，也不会扫描 AList / OpenList 目录。详见[本地归档库](./archive-library)。

归档库旁边的“在线内容”才会按需读取B站在线收藏夹、订阅合集、追番追剧、稍后再看和历史记录；它使用独立的有界在线缩略图缓存，规范BVID可手动进入账号的“手动归档”来源。详见[在线内容与封面](./online-content)。

## 7. 播放已验证归档

收藏夹详情会为远端已验证的MP4、M4V和WebM显示播放入口。播放器按收藏夹原顺序和分P顺序优先连接网盘临时直链，无法安全直连时自动使用BFB代理；播放不会改变备份状态，也不会缓存或转码完整视频。详见[归档播放器](./player)。
