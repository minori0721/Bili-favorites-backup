# 上传确认

网盘驱动常在WebDAV PUT返回成功后过几秒或几分钟才显示文件。BFB使用两阶段确认，普通新归档直接写入正式路径，不创建暂存目录，也不依赖MOVE；同时使用条件PUT避免在竞态中覆盖已有文件。

![上传完成后仍等待远端确认的收藏夹状态](/screenshots/upload-confirming.png){.doc-shot}

## 两阶段状态

1. 上传前整组检查当前收藏来源的旧证明和全部分P目标。完整旧证明与远端一致时保留旧版并跳过新版；没有旧证明时才准备向正式路径上传。
2. PUT返回`201/204`后，记录为`awaiting_verification`，页面显示“已上传·确认中”。
3. 后台立即检查一次，再按约`2秒、10秒、30秒、2分钟、5分钟、10分钟`复查；多分P分别从各自PUT被接受的时间计算，不会让较晚上传的分P沿用第一条文件的截止时间。
4. 大小一致后转为最终确认；所有目标完成后才清理本地文件。
5. 超过窗口后系统仍会低频只读复核。远端文件后来出现时自动收尾，不需要管理员重复点击。

持久上传会话包含全部分P时只创建一个会话级确认任务。它会批量恢复同一会话当前代际的文件状态，避免多个确认任务同时访问同一SQLite记录或重复探测同一远端目标；没有会话标识的旧记录仍按逐文件确认兼容处理。已完成会话重新上传时会递增代际并保留旧尝试明细，旧确认任务不会写入新代际。

确认期间的404属于“远端可见性延迟”，不会触发上传熔断，也不会重复PUT。条件PUT发现目标已经出现时，只有持久Session保存了本次PUT接受时间才允许按同大小确认；缺少该证明时即使大小相同也进入冲突流程。

## 超时与冲突

- 单个分P在自己的10分钟窗口内仍不可见：进入持久恢复状态并由后台低频只读复核；问题中心提供“立即重新检查”，只有管理员明确选择“继续上传”才为需要处理的文件授予一次重传。
- 本地补传文件丢失或大小变化：先逐文件复核远端。远端同大小时自动确认；全部缺失且收藏来源仍有效时最多自动重新下载3次。自动重下达到上限后停止循环并进入“待处理”。
- 完整旧归档：重新核验每个旧文件的路径、类型和大小；全部一致时继续使用旧版，不上传本地新版，也不改写旧媒体元数据。
- 未知同大小或同名异大小：不把远端文件当成本次上传结果，也不覆盖正式路径。异大小冲突和多分P混合状态会自动把本地完整分P组直接PUT到`_conflicts/upload-<任务ID>`；达到观察门槛的长期不可见也采用同样的隔离路径，多分P不会一部分沿用旧路径、一部分使用新版。
- 部分旧归档或旧证明漂移：同样进入独立候选，不自动拼接新旧分P。
- 候选上传不调用MOVE/COPY，重启后继续使用持久任务ID对应的同一目录。候选完整可见后，问题中心提供“保留现有归档”和“采用新候选”；两种选择都不会自动删除另一份物理文件。
- 采用候选后，当前播放来源切换到候选目录；正式旧路径、文件大小和旧媒体元数据仍保存在候选审计记录中，避免旧档变成无证明的孤立文件。
- 确定性的409冲突会先自动生成隔离候选，不会被普通同步重新覆盖提示；候选失败或远端状态仍未知时才停在人工恢复状态。重新确认只读检查，继续上传才携带一次性PUT权限；确认任务本身不会继承该权限。
- 确认阶段发现确定性409时，当前`verify_upload`会立即结束，人工恢复项会记录冲突分P和上传代际；处理旧远端文件后可重新确认，只有管理员明确点击“继续上传”才携带一次性重传权限。

“继续上传”的权限按相对文件路径保存。排队、远端预检、限速等待和只读确认都不会消耗它；只有对应文件即将发送PUT时才由当前任务租约在SQLite事务中原子消费。若进程在PUT前退出，授权仍可继续使用；PUT已经开始后失败则需要再次人工确认，避免重启后重复传输正文。

## 待处理问题中心

任务日志旁的“待处理”只显示系统无法完全自动解决、或需要管理员确认的事项。每项都说明原因、已经保护的数据和一个推荐操作，并提供不含远端路径、Cookie或凭据的诊断摘要。

### 单文件限制与媒体规格重试

远端返回单文件大小限制或严格候选未完成时，任务不会被视为成功，原上传任务会继续留在“待处理”。点击“换规格”后，BFB按需读取所有分P共同可用的B站画质×编码组合，并显示分辨率、帧率、预计成品大小、本地峰值、缓存余量和大小来源。接口已有大小直接使用；否则BBDown对用户选中的组合尝试HEAD或一字节Range，仍无法确认时明确标为码率估算。

用户可以只严格指定编码、只严格指定画质，或选择一个精确组合；未指定的维度沿用当前任务设置或编码偏好。提交后只为当前视频创建隔离下载目录和替换代次，不修改全局编码偏好；任一分P没有满足已指定的严格项时不会上传候选。B站探测失败时不会自动预选AV1或较低画质，必须由用户明确选择后才允许尝试。

原始本地文件和正式远端归档会一直保留，直到替换文件上传、逐文件确认和整组远端验证都完成。下载、上传或验证失败时会清理未确认的候选并恢复待处理状态；应用重启或迟到回调不会重复替换，也不会因为同大小文件就跳过本次证明。

- “立即重新检查”只读取远端状态。
- “重新下载”废弃失效上传尝试并重新排队，不删除远端文件，也不影响其他已验证收藏来源。
- “继续上传”属于普通缺失文件的明确授权；严格媒体规格失败不会显示该入口，必须重新选择规格或只读确认。
- “保留现有归档 / 采用新候选”会在执行前重新核验对应文件。同一候选决策串行处理，快速重复请求不会同时写入两种结果。
- 存储认证或配置错误会引导到设置页，临时网络错误继续使用原有退避和单任务探测，不要求用户反复点击。

自动恢复只处理可以安全判定的情况：远端已经出现且有本次PUT证明时自动收尾，远端暂时不可见或网络抖动时只读复核并退避。权限、网络故障和无安全候选父目录时不会自动写入；未知405不自动降画质、不切私有API，只进入脱敏证据复核。完整旧档加新候选仍保留两份，等待管理员选择“保留现有归档”或“采用新候选”。

::: warning 确认中不等于可清理
“已上传·确认中”计入已上传筛选并阻止重复下载，但本地成品仍必须保留，也不能开始画质替换。
:::
