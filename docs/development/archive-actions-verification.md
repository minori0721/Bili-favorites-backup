# 归档操作手工验证

本轮预览地址：`http://127.0.0.1:43211/`。账号、投稿、网盘文件和清理响应均为假数据，不使用真实 Cookie，不访问 B站或真实网盘。归档删除通过真实 SQLite/领域服务执行，对接内存网盘；“清理数据”和画质提交只模拟结果，不删除本机真实文件。

预览页左下角提供“重置示例”“模拟忙碌”“恢复空闲”“模拟删除失败”。每个删除场景前重置示例，避免上一步排除或删除影响下一步。模拟忙碌后重新打开清理窗口。

| 改动 | 点击路径 | 预期 |
| --- | --- | --- |
| 共用文件保护与真实删除量 | 归档库 → 全部归档 → “共用示例”卡片右上角菜单 → 收藏夹 A 的“管理归档” → 删除归档，并排除此视频 → 核对并确认 | 默认仅当前来源；显示 A 受影响、B 和 UP 保留；涉及 1 个文件、共享保留 1 个、预计实际删除 0 个、释放 0。确认后其他两个来源仍可播放 |
| 账号及整项订阅删除量 | 账号卡片“删除账号” → 选择同时清理归档；或 UP 卡片 × → 移除订阅并删除归档 → 核对 | 同样区分涉及文件、共享保留和预计实际删除/释放空间；整项订阅只处理该订阅，不删除其他来源仍引用的文件。账号删除响应在此预览中只模拟流程 |
| 同 BV 的独立副本 | 归档库 → “独立副本示例” → 收藏夹 A 的管理归档 → 删除 → 指定来源，只勾 A | 显示预计删除 1 个文件，释放 8 MiB 左右；B 的 16 MiB 副本保留 |
| 指定多个来源 | 共用示例 → 管理归档 → 指定来源 | 列出账号、收藏夹和 UP 名称，可逐项勾选；未勾选来源继续保留引用。全部取消时不能提交空范围 |
| 全局排除与恢复 | 共用示例 → 管理归档 → 保留归档，排除此视频 → 所有来源 → 确认 | 仅排除这个 BV，其他视频不受影响；规则也适用于以后新发现的来源。已有文件保留，解除全局排除不会同时清除来源自己的排除 |
| 单视频排除说明 | “历史示例” → 管理归档；或 UP 投稿选择 → 管理归档 | 显示“保留归档，排除此视频”；未排除不再表述为正在同步，已停用来源不会被误称为活动同步来源 |
| 订阅移除按钮一致性 | UP 卡片 × → 分别选择保留、删除 | 取消与确认按钮的字号、高度、内边距和圆角相同，颜色区分主次，宽度随文字变化 |
| 历史删除兼容 | 归档库 → “历史示例” → 删除本次归档 | 显示只删除当前来源、以后重新加入可正常归档，不悄悄创建永久排除 |
| 删除失败 | 左下角模拟删除失败 → 独立副本示例 → 管理归档 → 删除 A | 显示清理未完成、排除规则仍有效，原文件保留；关闭弹窗不等于取消后台任务 |
| 解除排除与进度 | 共用示例完成删除后 → 解除当前来源排除；失败示例中也尝试解除 | 正常完成后可解除，仍按来源的归档规则处理；失败清理未结束时明确拒绝，不能绕过后台清理。只归档选中的 UP 仍需按选择规则处理。进度能显示“清理完成”，旧进度不会覆盖新操作 |
| 清理忙碌一致性 | 左下角模拟忙碌 → 全局设置中的“清理数据” | 永久归档封面和依赖空闲的重要项目不可选；网页日志等日常清理仍可选。恢复空闲后重新打开可选 |
| 回滚备份与清空说明 | 清理数据 → 单独勾选回滚备份；再查看问号说明 | 备份位于高风险组，要求 DELETE；明确回滚副本不可恢复。说明中升级、重建容器不要求清空数据，远端视频与本地归档索引分别解释 |
| 画质重调计数 | 全局设置 → 检查可升级画质 → 勾选两个来源 → 确认重调 | 同一个 BV 显示“1 个视频、2 个归档来源”，列出 A/B，允许取消；不将共享下载次数当作视频数 |
| 排除后仍可管理 | UP 投稿选择 → 已备份视频 → 管理归档 → 保留归档并排除 → 关闭 | 同时显示“可播放”和“当前订阅已排除”，管理归档按钮仍在 |
| 明确恢复单个视频 | 何同学（只归档选中的）→ 已排除视频 → 管理归档 → 恢复归档此视频 | 确认后加入单独选择，现有文件复用；另一个“解除排除，按来源规则”只解除排除，不自动选中 |
| 停止失败清理 | 模拟删除失败 → 独立副本示例 → 删除 A → 失败 → 停止剩余清理 → 输入 STOP ARCHIVE CLEANUP | 停止后剩余文件仍在，排除保留，解除排除后可继续归档；未停止前不能通过批量选择或恢复绕过 |
| 保留订阅，清理历史 | 影视飓风 → 投稿选择 → 清理历史归档 → 核对并输入 DELETE ARCHIVE | 显示本次起点，说明取消更早的单独选择；订阅卡片保留并启用，改为从设定时间起，只有 3 个已归档视频新增排除，不排除所有 42 个候选 |
| 提交失败一致性 | 自动化故障注入：预览后改变远端目标再提交 | 排除、订阅 revision、清理任务一起回滚，恢复连接后原有效预览可重新提交 |

自动化用例：`tests/archive-video-actions.test.ts`、`tests/archive-deletion.test.ts`、`tests/up-subscriptions.test.ts`、`tests/storage-cleanup-service.test.ts`，以及 `tests/ui/archive-actions.spec.ts`。后者覆盖桌面、手机及横屏。

数据与来源在预览后变化时，应重新核对；不能继续执行旧的扩大范围预览。真实服务器没有用于手工删除验证。
