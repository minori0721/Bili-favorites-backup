# 传输带宽所有权与验证

`transfer-bandwidth.ts` 持有全局传输基础设施，由应用组装入口初始化、配置更新、配置重置及导入重载时设置最新额度。配置快照不覆盖运行中传输的额度。

- `ManagedAria2` 持有私有下载进程、运行代次、控制地址和任务归属。每次 BBDown 调用获得独立 GID 前缀及私有配置，完成后清除对应传输记录；停止单项只取消自己的 GID。引擎控制或取消失败时停止该引擎，关联任务沿用已有恢复流程，不能留孤立传输继续写文件。
- 下载调用登记覆盖引擎获取、BBDown 运行和传输释放；取消账号与应用关闭会等待传输释放完成。获取引擎期间被取消的调用不能再启动 BBDown。
- BBDown 负责解析、选流、媒体下载完成判断和合并；RPC 模式等待自己的 GID，而不是等待共享引擎退出。现有续传、TLS 验证和媒体核验仍保留。控制信息只写入本次创建的临时目录，权限为目录 700、文件 600，仅监听回环地址；本地控制连接绕过环境代理及全局请求分发器。
- `ByteRateLimiter` 持有上传额度和取消等待；同方向任务共用 FIFO 额度，按小块读取，不缓存完整媒体。统一 PUT 入口保留 Content-Length、条件写入、本地文件身份检查和远端核验。
- 限速字段不参与下载清单的画质和命名指纹。改变限速不使已有下载证据失效。
- 下载进展在共享引擎模式下读取已接收字节，避免预分配或合并改变目录大小。限速时只对完全无进展进行长窗口重试；极低额度延长窗口以覆盖网络块的等待时间，限速模式变化后重新建立观测窗口。

入口：`tests/transfer-bandwidth.test.ts`、`tests/download-progress.test.ts`、`tests/ui/transfer-bandwidth.spec.ts`；BBDown 的 `Aria2RpcTests.cs` 验证自身完成/失败、请求选项及回环地址约束。实际 aria2 与 BBDown 的联调使用回环假文件，Linux 发布仍需核验对应的固定组件。
