# UP 订阅实现与维护

UP 订阅是独立来源，不是收藏夹。公开身份为稳定 `sourceId` 和 UP UID；授权账号可更换。SQLite 中新增订阅、投稿目录、来源选择与全局排除表，数据库版本为 12。既有视频、文件证明、传输会话和任务表继续复用。SQLite 备份和 JSON 快照均保存订阅、投稿目录、选择与排除；恢复验证来源映射与目录证据，缺失或损坏时事务回滚，不混用导入前的规则。

现有任务和归档接口通过 `(userId, mediaId, bvid)` 路由。UP 来源分配独立负数路由键（从 -2 开始），仅作为旧队列接口的适配键；-1 仍是手动归档，正数仍是实际收藏夹 ID。路由键与 UID 无关，绝不加入账号的收藏夹列表。关系明确保存 `sourceKind: up` 和 `sourceId`。更换授权账号需在无同步、无传输及持久传输任务时取得维护租约，事务内迁移关系与凭据引用，来源和文件证明保留。

## 入口与依赖

- `up-subscriptions/bili-adapter.ts`：关注、搜索、UID 查询、投稿接口。全模块一条串行请求队列，默认至少间隔 2.5 秒，单请求 25 秒超时。WBI 密钥缓存六小时；风控响应冷却三十分钟，不连续更换接口重试。授权发生变化或停止时结果失效。
- `up-subscriptions/bili-decoders.ts`：完整页面字段和分页校验。坏条目让本页失败；合法空页正常返回；联合投稿不按主投稿 UID 过滤。搜索未提供关注状态时保持未知。
- `up-subscriptions/scan.ts`：由现有同步周期调用，没有另一个轮询器。每轮刷新最新页并分批推进历史扫描，重复页面与请求错误记录到当前订阅并冷却，不能标记历史完成，也不阻止其他独立订阅。轮次头部时间固定，分页中新增的投稿由下一轮补扫；不以目录缺项推断视频下架或删除。
- `scheduler/up-archive.ts`：记录真实来源关系，复用完整已核验的现有归档证明，否则调用现有下载/上传入队能力。队列去重、权限探测、重试、核验和清理沿用原流程。
- `repositories/up-subscriptions.ts`：订阅和投稿读写、选择规则、稳定分页。提供连接函数，导入更换数据库后不缓存旧连接。
- `up-subscriptions/service.ts` 与 `http/up-subscriptions.ts`：公开操作入口、版本冲突、持久选择及删除确认。API 在应用统一认证、同源保护、导入维护边界之后注册。
- `web/client/features/up-subscriptions`：首页入口、添加向导、投稿选择与视频管理；归档展示和播放继续使用现有归档库与播放器。

## 选择、排除和删除

全部、从现在、从日期、从视频、仅选中均按发布时间判断。日期和视频边界包含起点，不按列表位置判断。显式 include 可选择范围之外的投稿；来源 exclude 与全局排除优先于 include。规则调整及移除、重新添加订阅保留排除记录。

投稿选择是归档准入，取消单独选择不删除现有文件。新订阅的未选择候选仅存在投稿目录，不加入实际归档统计。

“不再归档”和“删除并不再归档”均支持当前来源与所有来源。预览不修改规则；确认时先提交排除，再启动现有归档删除用例。删除失败排除仍有效，并通过既有持久删除记录重试。来源删除保留其他来源引用的物理文件；视频级删除只影响同一 BV 的已确认来源，保留跨视频共享引用保护。解除全局排除不会清除来源自己的排除。

暂停或默认移除停止后续准入，不删除现有归档。整订阅删除复用 `scope=source, bvid=NULL` 的持久清理任务，不新增数据库 schema；快照覆盖该 UP 路由的所有关系，包括没有已核验文件的待处理关系，文件清理仅使用已有的可靠证明。移除、已知视频排除和删除任务登记在同一 SQLite 事务提交，登记失败全部回滚。执行前一次调用现有来源排空端口，统一处理该订阅的队列目标而不逐视频重复扫描队列，之后再次核对证明；迟到上传改变证明时停止并允许重新预览，绝不按旧列表继续删除。

删除清理只阻止这个来源的准入，其他来源按现有共享任务规则保留。未完成及失败的整订阅删除阻止重新添加、更换账号及解除排除；重新添加后已删除的旧视频仍保持来源排除。首页从持久删除记录读取进度和失败任务，完成记录展示一天，失败支持原任务重试或重新核对后替代旧任务。首页只在有进行中删除时轮询，工作区打开后共用其刷新，不重复轮询。已有归档、选择和排除记录不被物理删除。

内存预取任务在真正执行前重新核对来源准入；已排除目标不会开始下载、上传或画质替换，共享任务保留其他有效目标。取消未执行的普通任务恢复其待归档状态并保留本地证据，解除排除后仍可重新入队。已经传输完成的只读核验、已提交替换后的画质清理继续按原有证明收尾，不因排除而丢弃证明或清理计划。

暂停、恢复和更换授权账号保留历史页码和扫描水位；改变归档范围或重新添加时清零扫描水位，重新应用历史范围，避免旧水位挡住更早的投稿。已发现的视频与明确选择、排除记录仍然保留。

## 浏览与资源

关注和关键词搜索由用户显式提交，避免按键触发请求。投稿浏览、筛选和分页只读 SQLite；显式刷新才安排后台扫描。每轮最多读取四个页面，超大历史目录逐轮推进，以减轻 B站请求压力。

归档库提供 UP 目录；原 HTTP 地址继续兼容，播放和归档边界增加 UP 路由键支持。全库仍以 BV 聚合显示，来源关系和远端物理路径分别统计。

资源清单登记适配器、扫描工作流、服务缓存和前端控制器。停止顺序先关闭准入，再取消请求并等待同步周期排空。导入时清除预览缓存、重置扫描代次和适配器密钥缓存，失败不恢复写入。

## 验证与隔离预览

`tests/up-subscriptions.test.ts` 覆盖接口解码、联合投稿、选择与排除、来源复用、账号重绑定、共享删除、全局删除、删除失败、版本冲突、迟到响应、SQLite 事务故障、公开 HTTP 契约及请求串行与风控冷却。

UI 假服务使用相同服务、SQLite 仓储和归档用例，仅替换 B站及 WebDAV 为 Fake；不会读取真实 Cookie，也不会发送 B站请求或操作生产归档。预览只演示队列入队，模拟媒体不进行真实下载上传。新功能的真实扫描与传输接线由后端契约测试验证，线上验收和镜像构建另行进行。
